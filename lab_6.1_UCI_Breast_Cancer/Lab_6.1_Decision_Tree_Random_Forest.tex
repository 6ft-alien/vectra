    \section{Lab 6.1 --- Decision Tree and Random
Forest}\label{lab-6.1-decision-tree-and-random-forest}

\textbf{Dataset:} Breast Cancer Wisconsin (Diagnostic) --- UCI Machine
Learning Repository (569 instances, 30 numeric features, binary target:
malignant / benign). Loaded via
\texttt{sklearn.datasets.load\_breast\_cancer}, which is the exact UCI
dataset bundled for convenient offline use.

\textbf{Goal:} Implement a Decision Tree and a Random Forest classifier,
evaluate both with accuracy, precision, recall, F1-score and confusion
matrices, study the effect of key hyperparameters on performance and
overfitting, compare feature importance and training time, and conclude
which model is better suited to this dataset.

    \textbf{Observation:} The single Decision Tree concentrates almost all
importance on just one feature (\texttt{worst\ radius},
\textasciitilde65\%) plus a couple of runners-up --- it only needs a few
splits to separate the classes and, once a split works well, it
dominates the tree. The Random Forest spreads importance much more
evenly across \textasciitilde8-10 features (\texttt{worst\ perimeter},
\texttt{worst\ area}, \texttt{worst\ concave\ points},
\texttt{mean\ concave\ points}, etc., each in the 4-15\% range). This is
a direct consequence of \texttt{max\_features} forcing each split in
each tree to consider only a random subset of features --- a dominant
feature like \texttt{worst\ radius} isn't always available, so other
correlated/informative features get a chance to be used and are picked
up by the importance calculation.

The Random Forest outperforms the single Decision Tree on every test-set

\subsubsection{7.2 Overfitting behavior}\label{overfitting-behavior}

\begin{itemize}
\tightlist
\item
  \textbf{Decision Tree:} Very sensitive to \texttt{max\_depth} and
  \texttt{min\_samples\_split}. An unconstrained tree reaches 100\%
  training accuracy by memorizing the training set, and test accuracy
  \emph{peaks early} (around depth 3-4) and then \textbf{degrades} as
  depth increases --- textbook overfitting.
\item
  \textbf{Random Forest:} Much more robust. Individual trees can still
  be deep/overfit, but bagging (bootstrap sampling of rows) and random
  feature subsets (\texttt{max\_features}) de-correlate the trees'
  errors, so averaging their votes cancels out most of the overfit
  noise. Test accuracy rises with
  \texttt{max\_depth}/\texttt{n\_estimators} and then \textbf{plateaus}
  rather than falling.
\end{itemize}

\subsubsection{7.3 Feature importance}\label{feature-importance}

The Decision Tree's importance is concentrated in 1-2 dominant features
(\texttt{worst\ radius} alone accounts for \textasciitilde65\%), because
a greedy single tree just keeps re-using whichever feature best
separates the remaining data. The Random Forest distributes importance
across a broader set of correlated size/shape features
(\texttt{worst\ perimeter}, \texttt{worst\ area},
\texttt{worst\ concave\ points}, \texttt{mean\ concave\ points},
\texttt{worst\ radius}, \ldots), giving a more reliable and less noisy
picture of what actually matters, because \texttt{max\_features} forces
many different features to be tried as candidate splitters across the
ensemble.

\subsubsection{7.4 Training time}\label{training-time}

The Decision Tree trains roughly 40x faster than the tuned Random Forest
(a single tree vs.~200 trees). This trade-off is central to choosing
between them: Decision Trees are cheap, instantly interpretable (you can
draw the whole thing), and fast to retrain, while Random Forests cost
more compute and memory and are harder to interpret directly (though
feature importance and tools like SHAP help), in exchange for better and
more stable generalization.

\subsubsection{7.5 How each hyperparameter influences
behavior}\label{how-each-hyperparameter-influences-behavior}

\textbf{Decision Tree} - \texttt{max\_depth}: Directly caps how many
sequential splits (how much complexity) the tree can encode. Too shallow
-\textgreater{} underfitting (high bias); too deep -\textgreater{}
overfitting (high variance, as seen in the falling test-accuracy tail
past depth 6). - \texttt{min\_samples\_split}: Prevents a node from
splitting unless it has enough samples, acting as a smoother, less
aggressive regularizer than \texttt{max\_depth} --- it disallows splits
that would be based on very few, potentially noisy samples. -
\texttt{criterion} (\texttt{gini}/\texttt{entropy}/\texttt{log\_loss}):
Changes the impurity measure used to score candidate splits. It affects
\emph{which} split is chosen when several are similarly good, but has
much less effect on overfitting than the two hyperparameters above.

\textbf{Random Forest} - \texttt{n\_estimators}: More trees means more
votes to average, which reduces variance and stabilizes predictions ---
accuracy improves and then plateaus; it essentially never causes
overfitting on its own, only added compute cost. - \texttt{max\_depth}:
Controls the complexity of each individual tree in the forest. Because
bagging + random feature subsets already control the ensemble's overall
variance, letting individual trees grow deep (or even unrestricted) is
much safer here than in a standalone Decision Tree. -
\texttt{max\_features}: Controls how many features are considered at
each split. Smaller values increase the diversity (de-correlation)
between trees, which is what makes the ensemble's averaging effective;
setting it to use all features at every split makes the trees more
similar to each other and pulls performance back toward that of a single
tree.

\subsubsection{7.6 Conclusion}\label{conclusion}

For the Breast Cancer Wisconsin (Diagnostic) dataset, the \textbf{tuned
Random Forest is the better-performing model} --- higher test accuracy,
precision, and F1-score, and far more resistant to overfitting as
hyperparameters change --- at the cost of longer training time and
reduced interpretability compared to a single Decision Tree. If model
interpretability or inference speed is critical (e.g.~an embedded or
real-time clinical decision-support tool where a doctor needs to see the
exact decision path), a well-tuned, shallow Decision Tree
(\texttt{max\_depth\ \textasciitilde{}\ 4}) is still a strong,
transparent option that gives up only a small amount of accuracy.
